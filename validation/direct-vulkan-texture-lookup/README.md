# Shared texture-cache lookup and retirement

The cache formerly scanned all populated entries both when acquiring a texture and when releasing each completed sampling lease. The fixed entry allocation and pin-protected lifetime permit direct release through the entry pointer. Release still checks image identity and a nonzero pin count; it happens only through the existing GPU retirement callbacks.

A 1,024-slot (4 KiB per cache) lookup hint remembers the last pinned entry for a cheap texture/source hash. Every hint is validated against bounds, live image, source pointer, and the complete texture key, then against guest bytes/write tracking or render-target serial. Collisions and stale slots fall back to the original scan. No immutable-image, sampler, guest-memory coherence, budget, or GPU completion checks are bypassed. Lookup counters distinguish successful hints from scan work.

Validation: native VC3 and Android shared Vulkan builds passed. The existing texture-coherence fixture passed with synchronization validation, covering aliases, palettes, pinned versions, repeated mismatches, restored bytes, active write leases, eviction/reuse, sampler changes, and completion-gated source destruction. No new headset access. Unrelated host_input.c changes are present in both local game binaries and excluded from the commit.

Sequential local A/B uses /tmp/vc3-draw-submit-vc3 as control and /tmp/vc3-texture-lookup-vc3 as candidate, each with an independent copy of /tmp/vc3-draw-submit.cache, identical automated inputs, 2,100 frames and diagnostic flags. Reports retain hashes, environment and frame windows. This is local evidence, not Quest performance acceptance.

Results: both runs exited successfully at 2,100 frames. Candidate hints served 577,750 of 627,844 hits (92.0%); 7,404,849 entries were examined by fallback scans. All release scans are eliminated structurally. Excluding frames with nonzero pipeline-creation time, control -> candidate draw CPU was 1.913 -> 1.878 ms in combat, 3.263 -> 3.163 ms during activation, and 3.133 -> 3.056 ms while held. Completion CPU and GPU times rose slightly; this single sequential pair is insufficient to establish a net frame-time gain. Both remained about 60 FPS; candidate p95 ranged 21.42–22.91 ms. Scene execution and cache residency are not bit-identical. The reduction in lookup work is directly counted; repeatable FPS or pacing improvement is not claimed. See comparison.json for full values and frame counts. CPU geometry/color counters remained zero and texture fallback stayed at startup 1,030,144 pixels.
