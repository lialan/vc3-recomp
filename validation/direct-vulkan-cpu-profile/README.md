# Local CPU profile used to locate hidden extent transforms

On parent 59690c8, ran /tmp/vc3-queued-colors-vc3 for 2,100 frames with the prior inputs/cache. Triggered macOS sample on the live child near frame 1320, requesting 8 seconds at 1 ms. sample exited 0 and game exited 0. sample.txt is the complete local stack report; report.json records executable and game environment. Sampling heavily perturbs wall-clock waits and is not a performance comparison or Quest profile.

The deferred submission thread spends substantial sampled wall time in Vulkan/Metal driver calls and fence waits. Most other threads are waiting. The crucial actionable finding is raw_extent -> transform_vertex -> nv2a_vsh_run on the decode thread, plus one-vertex metadata interpretation in raster_batch. The former is generated eagerly by the deferred queue for screen-space programs although the Vulkan backend never consults raw.extent. Backend CPU-geometry counters do not cover these executor metadata transforms. The unsampled prior game log reported 81,527 extent queries / 338,160 interpreted vertices at its last executor statistics report.

Do not interpret blocked stack occupancy as CPU utilization. In particular the sampled main-thread BlockOnTime sleeping does not supersede the earlier unsampled fence-wait trace proving negligible steady-state polling time. The next fix removes unnecessary eager extent calculation using an explicit shared backend capability; it preserves the first-vertex metadata check because w0 controls texture routing. Full removal of CPU metadata work is not yet established.
