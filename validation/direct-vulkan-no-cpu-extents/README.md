# Avoid unused CPU vertex-program extent evaluation

Profiling found the deferred queue eagerly calling raw.extent for screen-space programs. That interprets vertices on the CPU even when the Vulkan renderer uses GPU vertex programs and never consumes the resulting extent. Prior executor statistics reported 338,160 CPU extent vertices; Vulkan's zero CPU-geometry counter did not cover them.

Added raw_no_extent to the shared Nv2aBackend contract. Zero retains legacy behavior. The deferred wrapper propagates the capability and clears the extent callback without evaluating it when opted out. Native Vulkan opts out only when raw_fixed is active and no raw observer or render_draw routing hook is configured. This is reusable backend capability negotiation, not a VC3-specific bypass. Other backends/observer configurations keep their metadata. First-vertex w0/d0 metadata evaluation remains because w0 also controls texture routing in the executor.

Native and Android kernel/runtime/Vulkan builds passed. The real queue fixture passed 128,000 draws for each capability setting, verifying exact callback counts (128,000 legacy / zero opt-out), copied extents when needed, inline aliases/lifetime, guest pointers, ring reuse and semaphore order. Vulkan texture-coherence tests passed with synchronization validation.

Local game run /tmp/vc3-no-cpu-extents uses the prior cache and automated input, plus RECOMP_PROF=1 (recorded separately in extra-environment.json because runner report filtering omits that variable). No sampling during this run. No Quest access or APK/push changes. host_input.c remains dirty and excluded. This removes one actual CPU graphics-emulation path; it does not prove all graphics metadata has moved off the CPU.

Run completed 2,100 frames, exit 0. Executor reports zero extent queries and zero CPU extent vertices throughout (last report 82,679 screen-space batches).
